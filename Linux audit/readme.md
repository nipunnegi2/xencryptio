# Crypto Audit JSON Output Documentation

## Overview

This document describes the structure and meaning of the JSON output generated by the crypto audit script. The output provides comprehensive information about cryptographic configurations, capabilities, and components on the target system.

## Root Structure

```json
{
  "with_sudo": { ... },
  "without_sudo": { ... }
}
```

## Privilege Level Sections

### `with_sudo` / `without_sudo`

These sections contain identical structure but different data based on privilege level:

- **`with_sudo`**: Data collected when running commands with sudo privileges
- **`without_sudo`**: Data collected when running commands without sudo privileges

Each section contains the following sub-sections:

## Data Sections

### `system_context`

Basic system information related to cryptographic capabilities.

```json
{
  "os_info": "Operating system details from /etc/os-release",
  "kernel_version": "Linux kernel version from uname -r", 
  "crypto_modules": ["Array of loaded cryptographic kernel modules"]
}
```

| Field | Type | Description |
|-------|------|-------------|
| `os_info` | string | Operating system name, version, and codename |
| `kernel_version` | string | Linux kernel version |
| `crypto_modules` | array | List of loaded cryptographic kernel modules |

### `openssl_crypto`

Information about OpenSSL installation and cryptographic capabilities.

```json
{
  "version_details": "Complete OpenSSL version and build information",
  "fips_mode_enabled": false,
  "available_algorithms": {
    "algorithm_name": {
      "available": true,
      "output_sample": "Sample hash output or null"
    }
  },
  "cipher_information": { ... },
  "protocol_support": [ ... ]
}
```

#### Main Fields

| Field | Type | Description |
|-------|------|-------------|
| `version_details` | string | Complete OpenSSL version information including build details |
| `fips_mode_enabled` | boolean | Whether FIPS mode is enabled in OpenSSL |
| `available_algorithms` | object | Hash algorithms supported by OpenSSL installation |
| `cipher_information` | object | Analysis of available cipher suites |
| `protocol_support` | array | Supported SSL/TLS protocol versions |

#### `available_algorithms`

Each algorithm (aes128, aes192, aes256, des, 3des, sha1, sha256, sha384, sha512, md5) contains:

- `available`: boolean indicating if algorithm is supported
- `output_sample`: string showing sample output or null if unavailable

#### `cipher_information`

```json
{
  "cipher_type_distribution": {
    "aes256_family": 40,
    "chacha20_family": 8,
    "other_cipher": 56
  },
  "total_ciphers": 144,
  "cipher_details": [
    {
      "name": "TLS_AES_256_GCM_SHA384",
      "type": "other_cipher"
    }
  ]
}
```

| Field | Description |
|-------|-------------|
| `cipher_type_distribution` | Count of ciphers by family |
| `total_ciphers` | Total number of available cipher suites |
| `cipher_details` | Array of first 20 ciphers with name and type |

**Note**: `cipher_families_available` field has been removed from output.

#### `protocol_support`

Array of protocol objects:

```json
{
  "protocol": "tls1_2",
  "type": "unknown_protocol",
  "cipher_count": 144,
  "available": true
}
```

| Field | Description |
|-------|-------------|
| `protocol` | Protocol name (ssl2, ssl3, tls1, tls1_1, tls1_2, tls1_3) |
| `type` | Protocol classification |
| `cipher_count` | Number of ciphers available for this protocol |
| `available` | Boolean indicating protocol support |

### `ssh_crypto`

SSH daemon cryptographic configuration and capabilities.

```json
{
  "version_info": "SSH version string from ssh -V",
  "version_details": {
    "version_number": "10.0",
    "major_version": 10,
    "distribution": "debian"
  },
  "algorithm_information": { ... }
}
```

#### Main Fields

| Field | Type | Description |
|-------|------|-------------|
| `version_info` | string | SSH version string from `ssh -V` |
| `version_details` | object | Parsed SSH version information |
| `algorithm_information` | object | Available SSH algorithms by type |

#### `algorithm_information`

Contains four algorithm types: `cipher`, `mac`, `kex`, `key`

Each type has this structure:

```json
{
  "total_count": 10,
  "algorithms": ["algorithm1", "algorithm2"],
  "algorithm_types": {
    "family_name": ["algorithm1", "algorithm2"]
  }
}
```

**Algorithm Type Classifications:**

- **cipher**: `aes128_ciphers`, `aes256_ciphers`, `chacha20_ciphers`, `3des_ciphers`, `des_ciphers`, `other_ciphers`
- **mac**: `sha1_macs`, `sha256_macs`, `sha384_macs`, `sha512_macs`, `md5_macs`, `other_macs`
- **kex**: `diffie_hellman_kex`, `ecdh_kex`, `curve25519_kex`, `other_kex`
- **key**: Currently all classified as `other_key`

### `certificates`

SSL/TLS certificates found on the system.

```json
{
  "certificates": [
    {
      "path": "/etc/ssl/certs/example.pem",
      "crypto_information": {
        "key_algorithm": "rsaEncryption",
        "key_size": 4096,
        "signature_algorithm": "sha256WithRSAEncryption",
        "characteristics": ["uses_sha256_signature", "rsa_algorithm"]
      }
    }
  ],
  "search_paths_used": ["/etc/ssl", "/etc/pki", "/usr/share/ca-certificates", "/etc/nginx/ssl", "/etc/apache2/ssl"]
}
```

#### Certificate Fields

| Field | Description |
|-------|-------------|
| `path` | Full filesystem path to certificate file |
| `crypto_information.key_algorithm` | Public key algorithm (rsaEncryption, id-ecPublicKey) |
| `crypto_information.key_size` | Key size in bits |
| `crypto_information.signature_algorithm` | Signature algorithm used |
| `crypto_information.characteristics` | Array of cryptographic characteristics |
| `search_paths_used` | Directories searched for certificates |

**Removed Fields**: The following fields have been commented out and won't appear in output:
- `subject`, `issuer`, `serial_number` (certificate identity information)
- `expires_within_90_days`, `expiration_date` (expiration information)
- `total_certificates_found`, `certificate_categories` (summary statistics)

#### Certificate Characteristics

- `uses_[hash]_signature`: Hash algorithm (md5, sha1, sha256, sha384, sha512)
- `rsa_algorithm`: RSA key type
- `ecdsa_algorithm`: ECDSA key type  
- `dsa_algorithm`: DSA key type

**Note**: `key_size_[N]_bits` characteristics have been removed from output.

### `hardware_crypto`

Hardware cryptographic acceleration and security features.

```json
{
  "cpu_crypto_features": {
    "aes_instructions": true,
    "random_number_generator": true,
    "secure_random_seed": true,
    "sha_extensions": false,
    "advanced_vector_extensions": true,
    "advanced_vector_extensions_2": true,
    "carry_less_multiplication": true
  },
  "crypto_feature_count": 6,
  "cpu_information": "Intel(R) Core(TM) i7-10870H CPU @ 2.20GHz",
  "tpm_devices": [],
  "random_devices": ["/dev/random", "/dev/urandom"],
  "crypto_devices": []
}
```

#### CPU Crypto Features

| Field | Description |
|-------|-------------|
| `aes_instructions` | AES-NI hardware acceleration support |
| `random_number_generator` | RDRAND instruction support |
| `secure_random_seed` | RDSEED instruction support |
| `sha_extensions` | SHA hardware acceleration support |
| `advanced_vector_extensions` | AVX instruction set support |
| `advanced_vector_extensions_2` | AVX2 instruction set support |
| `carry_less_multiplication` | PCLMULQDQ instruction support |

### `system_security`

System-level security and compliance settings.

```json
{
  "fips_kernel_mode": false,
  "crypto_libraries": ["libssl3.so", "libcrypto.so"],
  "kernel_crypto_algorithms": ["name : sha256", "name : aes"],
  "system_entropy": 256
}
```

| Field | Type | Description |
|-------|------|-------------|
| `fips_kernel_mode` | boolean | FIPS 140-2 kernel mode status |
| `crypto_libraries` | array | Installed cryptographic libraries |
| `kernel_crypto_algorithms` | array | Kernel-level cryptographic algorithms |
| `system_entropy` | integer | Available system entropy in bits |

## Removed Sections

The following sections have been completely commented out and will not appear in the JSON output:

### `information_summary`
The entire information summary section has been disabled, including:
- `audit_timestamp`
- `system_overview` 
- `cryptographic_inventory`
- `configuration_details`
- `feature_availability`

## Data Types

- **boolean**: true/false values
- **integer**: Numeric values (counts, sizes, entropy levels)
- **string**: Text data (versions, paths, algorithm names)
- **array**: Lists of items (algorithms, file paths, modules)
- **object**: Nested structures containing related fields

## Output Structure Summary

The current output structure contains only two main sections:

1. **`with_sudo`**: Complete cryptographic audit data collected with elevated privileges
2. **`without_sudo`**: Same structure but potentially limited data collected without privileges

Each section contains:
- `system_context`: Basic OS and kernel information
- `openssl_crypto`: OpenSSL capabilities and configuration
- `ssh_crypto`: SSH cryptographic algorithms and version info
- `certificates`: Certificate inventory (first 10 certificates only)
- `hardware_crypto`: Hardware acceleration features
- `system_security`: System-level crypto configuration

## Usage Notes

1. **Simplified Output**: Many summary and categorization fields have been removed to focus on raw data collection.

2. **Certificate Limitations**: Only the first 10 certificates are included in output, without expiration or categorization analysis.

3. **No Summary Statistics**: Certificate counts, algorithm summaries, and feature availability summaries are not included.

4. **Raw Data Focus**: The output now primarily contains raw cryptographic configuration data without interpretation or analysis layers.

## Example Usage

```bash
# Run the audit
python crypto_audit.py

# Parse specific information from JSON output
jq '.with_sudo.openssl_crypto.fips_mode_enabled' audit_output.json
jq '.with_sudo.ssh_crypto.algorithm_information.cipher.total_count' audit_output.json
jq '.with_sudo.certificates.certificates[].crypto_information.key_size' audit_output.json
```
